# پنل مدیر و مدل سراسری

تاریخ بررسی: ۱۴ اکتبر ۲۰۲۶.

وضعیت: پیاده‌سازی و آزمون محلی تکمیل است؛ اتصال موفق به ارائه‌دهنده با کلید واقعی هنوز تأیید نشده است.

## استفاده

برای ساخت اولین حساب مدیر، در ترمینال پروژه دستور زیر را اجرا و ایمیل نمونه را جایگزین کن.

```powershell
docker compose exec api python -m researchos.cli create-admin --email you@example.com
```

رمز ۱۲ تا ۲۵۶ کاراکتری به‌صورت مخفی در همان ترمینال گرفته می‌شود.

برای مدیرکردن یک حساب فعال موجود:

```powershell
docker compose exec api python -m researchos.cli grant-admin --email you@example.com
```

از [پنل مدیر](http://localhost:3000/admin) وارد شو.

پروتکل، آدرس پایه، شناسهٔ دقیق مدل و کلید را وارد کن و دکمهٔ آزمون و اعمال را بزن.

کلید را در چت یا مخزن قرار نده.

## قابلیت‌ها

- نمایش شمار حساب‌ها، حساب‌های فعال، پروژه‌ها و مقاله‌ها.
- فعال یا غیرفعال‌کردن کاربران عادی با کنترل نسخه؛ غیرفعال‌سازی نشست‌ها را لغو می‌کند.
- حفاظت از حساب خود مدیر و حساب‌های مدیر دیگر؛ تعیین نقش از دستور محلی انجام می‌شود.
- تنظیم سراسری `Gemini`، ارائه‌دهندهٔ سازگار با `OpenAI` یا نمونهٔ صریح `Mock`.
- کلید رمز‌شده با `AES-256-GCM`، بدون نمایش کلید یا متن رمز‌شده در پاسخ.
- آزمون با یک پیام ثابت، بدون ارسال مقاله و بدون تلاش مجدد خودکار.
- فعال‌سازی اتمی پس از پاسخ متنی معتبر، بررسی دوبارهٔ دسترسی و نشست مدیر و تطبیق نسخهٔ تنظیم.
- حفظ تنظیم فعال هنگام شکست اتصال، پاسخ نامعتبر، پایان مهلت یا تغییر هم‌زمان تنظیم.
- حذف کلید تنظیم‌های شکست‌خورده، منسوخ یا جایگزین‌شده؛ پاک‌سازی آزمون رهاشده پس از پنج دقیقه.
- نمایش بیست آزمون اخیر با وضعیت، زمان و مصرف موجود؛ مصرف نمونهٔ محلی مشخص است و هزینهٔ نامعلوم ساخته نمی‌شود.

مدیر به متن مقاله یا کلید شخصی کاربران دسترسی اضافه دریافت نمی‌کند.

مسیر شخصی صریح کاربر بر مدل سراسری تقدم دارد؛ خرابی مسیر شخصی باعث ارسال پنهانی به ارائه‌دهندهٔ سراسری نمی‌شود.

## آدرس و کلید

برای ارائه‌دهندهٔ سازگار، آدرس پایهٔ عمومی `HTTPS` با پورت `443` لازم است، مانند `https://api.example.com/v1`.

سرور مسیر `chat/completions` را اضافه می‌کند؛ آدرس کامل آن را در فرم وارد نکن.

ارائه‌دهنده باید قرارداد `Chat Completions` و پارامتر `max_completion_tokens` را پشتیبانی کند.

آدرس خصوصی، اطلاعات ورود در آدرس، پارامتر پرس‌وجو، آدرس مستقیم `IP` و تغییر مسیر پذیرفته نمی‌شوند.

همهٔ پاسخ‌های `DNS` بررسی می‌شوند و اتصال به همان `IP` عمومی تأییدشده انجام می‌شود؛ نام میزبان برای بررسی گواهی و `SNI` حفظ می‌شود.

برای `Gemini` فقط آدرس رسمی پذیرفته می‌شود.

کلید خالی فقط برای همان پروتکل و آدرس پایهٔ فعال، کلید قبلی را بازاستفاده می‌کند؛ تغییر مقصد نیازمند کلید جدید است.

تغییر کلید ارائه‌دهنده، به تغییر کلید اصلی رمزنگاری سرور نیاز ندارد.

## شواهد بررسی

| بررسی | نتیجه |
|---|---|
| کل مجموعهٔ بک‌اند در `Docker` با پایگاه داده، صف و سرویس‌های واقعی | ۱۵۷ آزمون موفق؛ یک آزمون مختص فایل خارج از تصویر بک‌اند اجرا نشد |
| آزمون‌های مستقل میزبان، شامل آزمون فایل تنظیمات فوق | ۹۱ آزمون موفق |
| آزمون‌های فرانت‌اند | ۱۰ آزمون موفق |
| بررسی `Ruff`، `ESLint`، نوع‌ها، قفل وابستگی و ساخت محصول | موفق |
| تطبیق مهاجرت با مدل داده | موفق |
| مسیر واقعی `HTTP` از پراکسی فرانت‌اند | ورود مدیر، منع کاربر عادی، فعال‌سازی `Mock` و حفظ تنظیم هنگام رد ورودی موفق |
| وضعیت سرویس‌های برنامه | پایگاه داده، صف، رابط، سرور، پردازشگر و نگهداری سالم |

آزمون‌های کنترل‌شدهٔ پاسخ ارائه‌دهنده، شبیه‌سازی‌اند و تأیید اتصال واقعی محسوب نمی‌شوند.

تنظیم و حساب‌های موقت آزمون واقعی پاک شده‌اند و کلید واقعی در آزمون‌ها استفاده نشده است.

بازبینی بصری پنل در مرورگر انجام نشده است.

تحلیل علمی مقاله و کنترل رضایت ارسال سند در مرحلهٔ ۵ پیاده‌سازی می‌شوند؛ آزمون اتصال فعلی این قابلیت‌ها را تأیید نمی‌کند.
